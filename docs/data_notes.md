# Данные и замеры

Запросы: [`sql/data_quality.sql`](../sql/data_quality.sql), результат: [`results/data_quality.txt`](../results/data_quality.txt).

## Что нашлось в логах

- **Написание.** 9% строк (89 365 из 992 318) отличаются регистром или пробелами, а 11 018 написаний сводятся к 2632 запросам. Нужен `lowerUTF8`: обычный `lower` не меняет кириллицу.
- **Боты.** `90000001` и `90000002` по кругу повторяют пару запросов. У «платье → странный запрос» 500 событий, но всего один пользователь, поэтому порог в 5 её отсекает. Если считать события, эта пара попала бы в теги.
- **Чего нет.** NULL, пустых запросов, полных дублей, одинакового времени у одного пользователя и символов, кроме букв, цифр и обычных пробелов.

## Решения, которые проверены на данных

| Решение | Сравнение | Результат |
|---|---|---|
| `LowCardinality(String)` | со `String` | 7,66 МиБ против 13,44 МиБ |
| `ORDER BY (user_id, timestamp)` | с `(timestamp, user_id)` | 7,66 МиБ против 8,80 МиБ |
| `uniqExact` | с `uniq` | 0 отличий на 4110 парах, но точность не зависит от объёма |
| Сортировка по `tag` при равенстве | без неё | результат стабилен: у 48 запросов равенство на границе 10-го и 11-го места |
| Граница `<=` 30 минут | с `<` | в логах 22 паузы ровно по 30 минут, со строгим сравнением теряется 1 тег |

## Нормализация в Go и в SQL

Сервис и SQL нормализуют независимо. Интеграционный тест сверяет результат на всех 11 018 запросах из логов и на отдельном наборе строк: расхождений нет.

На символах, которых нет в логах, различия есть: греческая финальная сигма (`ΣΑΣ`), турецкая `İ` и некорректный UTF-8. Такой запрос сохранится в одной форме, а искаться будет в другой, поэтому теги для него не найдутся. Для магазина с кириллицей и латиницей это неважно, а для других алфавитов нормализацию лучше выполнять в одном месте.

Пробелами считается `\s`: пробел, табуляция и переводы строк. Неразрывный пробел не входит.

Запросы из одних пробелов отбрасываются до поиска соседей, поэтому не разрывают пару.

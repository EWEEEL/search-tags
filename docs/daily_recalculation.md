# Ежедневный пересчёт тегов

Как обновлять теги каждый день, не пересобирая всё с нуля.

**Что хранить.** Пользователей нельзя просто сложить между днями: один человек посчитается дважды. Поэтому храним не числа, а состояния агрегатов: таблица `AggregatingMergeTree` с партициями по дням и колонками `day, query, tag, uniqExactState(user_id)`. Если хватит приближённого счёта, подойдёт более компактный `uniqCombinedState`.

**Что считать ночью.** Пары только за новый день. Чтобы не терять пары через полночь, читаем ещё последние 30 минут предыдущего дня, а пару относим к дню второго запроса.

**Как записывать.** Готовая партиция заменяется целиком через `REPLACE PARTITION`. Повторный запуск безопасен, а опоздавшие данные исправляются пересчётом одного дня.

**Как собирать теги.** Объединяем состояния через `uniqExactMerge` за нужное окно, например 30 дней, применяем те же порог и топ-10 и подменяем результат через `EXCHANGE TABLES`. Сервис при этом не простаивает.

**Как чистить.** Партиции старше окна удаляются по TTL.
